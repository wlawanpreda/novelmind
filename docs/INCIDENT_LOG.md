## 📌 สรุปรายการปัญหาที่พบ (Root Cause & Permanent Fixes)

### 1. การรั่วไหลของข้อความ AI คุยเล่น (Meta-talk & Persona Leaks)
* **อาการ:** มีข้อความเช่น *"โอ้โห! ดราฟต์นี้มีของ"*, *"ในฐานะ Chief Literary Editor"*, *"มาครับ! ได้เวลาใส่เกลือเพิ่มความเค็ม"*, *"ฉบับขัดเกลาโดย..."* หลุดเข้าไปในเนื้อหาบทนิยายและชื่อตอนบน ReadAWrite
* **สาเหตุรากเหง้า:**
  1. โมเดล LLM ตอบกลับมาพร้อมบทสนทนาทักทายของตัวละครสมมุติ (Persona preamble)
  2. โค้ดบันทึกไฟล์ในบาง Stage ไม่ได้เรียกใช้ฟังก์ชันตัดคำ (`strip_meta` / `sanitize_meta_talk`) ก่อนเขียนลงดิสก์
* **การแก้ไขถาวร (Permanent Fix):**
  - เพิ่ม Blacklist คำต้องห้ามลงใน `_META_MARK` (`agent_writer.py`) และ `FORBIDDEN_PATTERNS` (`agent_auditor.py`)
  - บังคับให้ทุกจุดที่มีการบันทึกไฟล์ Chapter / AudioScript / Publish Kit ต้องผ่าน `sanitize_meta_talk()` 100%
  - สแกนตรวจสอบอัตโนมัติทั้งระบบผ่าน `agent_auditor.py --scan`

---

### 2. ตัวอักษรจีน/ญี่ปุ่น (CJK) ปนเปื้อนในนิยายไทย
* **อาการ:** พบคำศัพท์ภาษาจีน เช่น `魔王` (จอมมาร), `魑魅魍魉` (ภูตผีปีศาจ), `神器` (ศาสตราวุธเทพ), `防卫` (ป้องกัน) ในบทนิยาย
* **สาเหตุรากเหง้า:**
  1. การ Scout ไอเดียจากเว็บต่างประเทศ (Syosetu / นิยายจีน) มีคำเฉพาะตกค้างในขั้นตอน Outline
  2. โมเดล Local LLM (เช่น Qwen / Ollama) มี Vocabulary Bias ดึงคำศัพท์จีนมาใช้ในบริบทกำลังภายใน/แฟนตาซี
* **การแก้ไขถาวร (Permanent Fix):**
  - เพิ่ม CJK Auto-Translator ใน `sanitize_meta_talk()` เพื่อแปลงศัพท์ภาษาจีน/ญี่ปุ่นเป็นภาษาไทยที่สละสลวยทันที
  - เพิ่มกฎตรวจจับ CJK ใน `agent_auditor.py` หากพบตัวอักษรจีนเกินเกณฑ์จะทำการแก้ไขหรือแจ้งเตือนทันที

---

### 3. ไฟล์ JSON ดิบถูกบันทึกเป็นบทนิยาย (Raw JSON Wrapper)
* **อาการ:** ไฟล์บทนิยายบางไฟล์ขึ้นต้นด้วย `{"full_prose": "..."}` หรือ `{"analysis": [...]}`
* **สาเหตุรากเหง้า:** โมเดลตอบกลับมาในรูป JSON ตามคำสั่งเดิม แต่สคริปต์ไม่มีตัวแกะ (Unpack) ดึงเนื้อหาข้อความออกมา
* **การแก้ไขถาวร (Permanent Fix):**
  - เพิ่มระบบ Auto-Unpack JSON ใน `sanitize_meta_talk()` ตรวจจับคีย์ `revised_content`, `full_prose`, `chapter_text`, `paragraphs` แล้วแยกเฉพาะเนื้อหาร้อยแก้วออกมาให้อัตโนมัติ

---

### 4. ไฟล์เปล่า 0-Byte (Empty Placeholder Files)
* **อาการ:** มีไฟล์บทที่ 5–8 ว่างเปล่าขนาด 0 ไบต์จำนวน 227 ไฟล์ ทำให้เกิดความสับสนในการเผยแพร่
* **สาเหตุรากเหง้า:** มีการสร้างไฟล์จองล่วงหน้าก่อนที่โมเดลจะเขียนเนื้อหาจริง
* **การแก้ไขถาวร (Permanent Fix):**
  - ลบไฟล์ 0-byte ทั้ง 227 ไฟล์ออกจากระบบ
  - ปรับระบบให้สร้างไฟล์เฉพาะเมื่อมีเนื้อหาจริงผ่านเกณฑ์ขั้นต่ำ (>1,500 ตัวอักษร) เท่านั้น

---

### 5. คอขวดการนำไฟล์ไปเผยแพร่จริง (Manual Friction in Publishing)
* **อาการ:** ทรัพยากร (เนื้อหา, ภาพปก, วิดีโอ Teaser, คำโปรย) กระจายตัวอยู่หลายโฟลเดอร์ ต้องเปิดสลับไปมาหลายหน้าต่าง
* **การแก้ไขถาวร (Permanent Fix):**
  - พัฒนาระบบ `daily_packager.py` จัดแพ็กเกจปล่อยงานรายวัน 1-Click Folder (`Daily_Releases/Day_XX/`) รวมไฟล์ทุกอย่างไว้ในที่เดียวพร้อม Checklist

---

### 6. ความต่อเนื่องของเนื้อหาเรื่องยาว (Story Bible & Continuity)
* **อาการ:** เรื่องที่มีหลายตอน (5+ ตอน) เสี่ยงต่อการลืมกฎของโลกหรือสถานะตัวละคร
* **การแก้ไขถาวร (Permanent Fix):**
  - ติดตั้ง `story_bible.py` เก็บประวัติเหตุการณ์ย่อ, กฎของโลก, และปมที่ยังไม่เฉลย ป้อนเข้า Prompt ของ `chapter_continuer.py` ทุกครั้งที่เขียนตอนต่อ
